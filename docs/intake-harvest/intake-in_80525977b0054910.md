How to plan, not a product design.

When the target repo already has docs/mocks/home.html for another surface, park the new wireframes in docs/mocks/<slug>/home.html, empty.html, and error.html. Point validate-vision-pack.py --mocks-dir at that subfolder. Do not overwrite the existing trio.

Before filing, read open issues that share the UI noun. Compare the Goal line. A page that is required to drop a field is a different slice from a page that must show that field. Do not merge those drafts into one issue.

Evidence: an existing repo already had both a product-root mock trio and a topic subfolder (digest-fuel). A same-day UI pack used the same screen name and explicitly dropped the field this pack had to show. The park used a new mocks/<slug> folder and separate issues.
